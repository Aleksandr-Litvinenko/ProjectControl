## 2026-08-02 — карта доступа к API собирается из кода

**Что добавлено**

- `tools/audit-routes.mjs` — статический анализ прав доступа. Без зависимостей,
  на стандартном Node 20.
  - Идёт от `apps/api/src/index.ts` по всем `app.use(...)`, спускается
    во вложенные роутеры (вся админка примонтирована через `routes/admin/index.ts`),
    наследует охрану уровня роутера.
  - Для каждого маршрута собирает `requireAuth`, `requireRole(...)`,
    `assertAccess` / `assertWrite` / `canWriteProject` и скоуп выборки
    (`projectScopeWhere` / `accessibleProjectIds`).
  - Разворачивает охрану, спрятанную за вызовами: именованную мидлварь
    (`preAuthWrite` в `routes/checklist.ts`) и цепочку через границы файлов —
    `GET /api/dashboard` → `buildDashboard` → `scopedWhere` → `accessibleProjectIds`.
  - Падает с кодом `1`, если находит маршрут, до которого можно дойти без
    единой проверки прав и которого нет в `PUBLIC_ALLOWLIST`.
- `docs/ACCESS-MAP.md` — сгенерированная карта: **52 маршрута**, кто и что
  может по каждому.

**Что изменено**

- `package.json` — команды `audit:routes` (пересобрать карту) и
  `audit:routes:check` (только проверка, для CI или pre-push).
- `README.md` — в разделе про RBAC ссылка на карту и обе команды.

**Зачем**

Ролевая модель — главное, что этот продукт обещает: РП видит свои проекты,
заказчик не видит внутреннюю загрузку специалистов. Проверки при этом
размазаны по трём слоям — `requireRole` в маршруте, `assertWrite` в теле
обработчика, `accessibleProjectIds` внутри сервиса. Ответ на вопрос
«кто может скачать документ проекта» до этого собирался чтением четырёх файлов.

Таблицу прав, написанную руками, поддерживать невозможно: она устаревает
на первом же новом эндпоинте, причём молча. Поэтому карта не пишется,
а собирается из кода.

Проверка на маршруты без охраны — не теория: за такую ошибку платят утечкой
документов, а глазами в диффе она не видна, потому что выглядит как обычный
новый маршрут.

**Совместимость**

Ни строчки продуктового кода не тронуто — только новый инструмент,
сгенерированный документ и две команды в `package.json`. Инструмент читает
файлы и ничего не выполняет.

Текущий результат: 52 маршрута, незащищённых нет. Публичны намеренно только
`POST /api/auth/login` и `POST /api/auth/logout` — они перечислены
в `PUBLIC_ALLOWLIST` в самом скрипте.
