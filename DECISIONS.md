## Этап 0 — инспекция окружения (2026-05-31)

### Локальная машина (Mac разработчика)
- macOS 26.5, Apple Silicon (arm64), 18 ядер, 48 ГБ RAM.
- Node v20.20.2, npm 10.8.2, git 2.50.1, Homebrew 5.1.12.
- Docker / PostgreSQL / nginx **не установлены** локально.
- **Решение:** на локальную машину ничего не ставим. Код пишем локально, всё исполнение (install / build / migrate / run) — на сервере.

### Сервер развёртывания (целевой)
- Хост: управляемый VPS; имя узла и IP не публикуются в репозитории.
- DNS: `projectcrm.ru` указывает на целевой сервер.
- ОС: **Ubuntu 24.04.4 LTS**, kernel 6.8.0, x86_64.
- Ресурсы: **2 vCPU, 4 ГБ RAM** (без swap), диск 20 ГБ (свободно ~13 ГБ).
- Установлено: Node v20.20.2, npm 10.8.2, **Docker 29.x + Compose v5**, git 2.43, **nginx 1.24**, **pm2 7**, **certbot 2.9**. Клиент `psql` не установлен (Postgres поднимем в Docker).

### Что уже крутится на сервере (на момент старта)
- **nginx** на :80 со сайтами:
  - `app` (`default_server`) → статика `/opt/app/frontend/dist` + `/api` → `127.0.0.1:3000`. Это **старый проект** — по указанию заказчика **неактуален**, заменяем на ProjectControl.
  - `game.projectcrm.ru` → `127.0.0.1:3100` (pm2 `crown-mp`, `/opt/game`) — **сторонний проект, не трогаем**.
  - `gamecodex.projectcrm.ru` (+ опечатка `gamecodex.projectrm.ru`) → `127.0.0.1:8090` (`/opt/gamecodex`) — **не трогаем**.
- Нативный PostgreSQL на `127.0.0.1:5432` + Docker-стек `app` (`app-db-1`, `app-backend-1`, `app-frontend-1` — frontend упал). Относятся к старому проекту.
- **TLS:** сертификатов нет (`certbot certificates` → No certificates found), :443 не слушается. Текущий сайт по факту HTTP. Для `projectcrm.ru` выпустим Let's Encrypt на этапе деплоя.

### Вывод по развёртыванию
Docker есть → используем **docker compose** для нашего стека (db + api + web), порты только на `127.0.0.1`. Внешний вход и TLS даёт **существующий host-nginx** (он уже обслуживает несколько сайтов; второй nginx на :80/:443 не поднимаем). Наш сайт займёт `projectcrm.ru` (и `default_server`), соседние поддомены не затрагиваются.

## Технические решения

| # | Решение | Обоснование |
|---|---|---|
| D1 | **Express** (а не Fastify) | Зрелая экосистема, простая интеграция multer; для ~35 пользователей производительности с запасом. |
| D2 | **Аутентификация: JWT в httpOnly-cookie** (а не серверные сессии) | Без внешнего session-store, stateless, безопасно (httpOnly+SameSite). |
| D3 | **bcrypt (bcryptjs)** для паролей | Стандарт, без нативной сборки → надёжно ставится в Docker. |
| D4 | **PostgreSQL в Docker** (отдельный том), а не нативный серверный pg | Изоляция от старого проекта и от других сервисов; чистый бэкап/переезд через volume. |
| D5 | **Монорепо на npm workspaces** (`apps/api`, `apps/web`) | Только npm доступен; не тащим pnpm/yarn. |
| D6 | **Дев локально → деплой на сервер по rsync**, исполнение на сервере | Совпадает с прежним подходом проекта (файлы синкались с Mac), не ставим стек на Mac. |
| D7 | **Проект на сервере: `/opt/projectcontrol`** | Не пересекается со старым `/opt/app`; старый стек гасим/чистим после проверки нового. |
| D8 | **Экспорт: `exceljs` (xlsx) + серверный рендер PDF** | Кириллица в xlsx из коробки; для PDF — встроенный шрифт с кириллицей. |
| D9 | **Гант: собственный компонент (SVG/CSS)** | Полный контроль над кириллицей и адаптивом, без тяжёлых зависимостей. |
| D10 | Пороги здоровья — в конфиге (`HEALTH_*` env) | По требованию ТЗ (раздел 7). Дефолты: дедлайн «скоро» 7 дней, перегруз 🟡 >100%, 🔴 >120%. |

## Seed-доступы (демо)

Seed создаёт локальных демонстрационных пользователей, но не содержит и не выводит пароли. Перед запуском необходимо задать уникальные `SEED_ADMIN_PASSWORD` и `SEED_DEMO_PASSWORD` через окружение. Seed предназначен только для локальной или изолированной среды и не должен запускаться на production.

| Логин | Роль |
|---|---|
| `admin` | Руководитель ПО (pmo_admin) |
| `pm1`, `pm2`, `pm3` | Руководители проектов |
| `spec1` … `spec5` | Специалисты |
| `obs1`, `obs2` | Наблюдатели |
| `client1`, `client2` | Заказчики |

Демо-проекты: ERP (🔴 просрочен обязательный «План» + перегруз spec1=140%), Интеграция (🔴 срок проекта в прошлом), ЗУП (🟡 дедлайн обязательного скоро), БП (🟢 в плане).

## Решения этапа деплоя (11)

- **D15. Сломанная bridge-сеть Docker на хосте.** На сервере отсутствует предопределённая сеть Docker `bridge`, встроенный DNS контейнеров (127.0.0.11) не отвечает, а пользовательская сеть заняла подсеть docker0 (172.17/16). Перезапуск демона (`systemctl restart docker`) починил бы это, но он бы уронил контейнеры соседнего проекта (`app-*`) — недопустимо. Решения-обходы:
  - **Сборка образов:** `docker build --network=host` (compose build не пробрасывает `--network`), теги `projectcontrol-api`/`projectcontrol-web`, затем `docker compose up --no-build`.
  - **Рантайм:** `api` и `web` — в `network_mode: host` (как и соседний проект на этом сервере). БД (`db`) — в обычной сети с публикацией `127.0.0.1:5433`; API ходит в неё через loopback (`DATABASE_URL=...@127.0.0.1:5433`). Публикация портов работает независимо от встроенного DNS.
- **D16. Провайдерский edge терминирует публичный HTTPS.** Внешний `projectcrm.ru:443` отдаёт wildcard-сертификат `*.projectcrm.ru` (выписан провайдером Jino, не наш) и проксирует на origin **:80**. Поэтому:
  - На origin **не делаем** редирект HTTP→HTTPS (иначе бесконечный цикл: edge→origin:80→301→…). Контент отдаём на :80.
  - Собственный Let's Encrypt-сертификат (`certbot`) для `projectcrm.ru` оставлен в блоке `:443` origin для прямого доступа по IP/без edge; авто-renew настроен certbot'ом.
- **D17. Dockerfile API ставит devDependencies** (`npm install --include=dev`, без `NODE_ENV=production` на этапе сборки): `tsc` нужен для сборки, а `prisma` CLI и `tsx` — в рантайме (миграции `prisma migrate deploy`, seed через `tsx`).
- **D18. Старый проект `/opt/app`** (контейнеры `app-*`, nginx-сайт `app`) отключён (сайт `app` убран из `sites-enabled`, бэкап конфига в `/root/app.nginx.bak.*`). Контейнеры `app-*` пока оставлены остановкой не тронуты; удаление — по согласованию.

## Открытые вопросы / на потом

- Push в GitHub (`github.com/Aleksandr-Litvinenko/ProjectControl`) требует авторизации (нет gh CLI/токена локально). Коммитим локально; пуш — когда будут предоставлены креды/токен.
- Старые контейнеры `app-*` и каталог `/opt/app` можно удалить после подтверждения, что старый проект больше не нужен (освободит ~место и порт 3000).
- Поддомены `game.*`/`gamecodex.*` не имеют публичных DNS-записей (обслуживаются по `Host`-заголовку); их не трогали.
